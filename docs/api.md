# API Specification

Base URL: `http://localhost:8000` (dev). All routes are mounted under `/api/v1`. Interactive, always-current docs are auto-generated by FastAPI at `/docs` (Swagger) and `/redoc`; this page is a hand-written reference of the same contract plus the error semantics that OpenAPI doesn't capture well.

**Authorization:** none yet. `user_id` is a self-reported UUID the client persists in `localStorage` after `POST /users/register` — see [ADR: minimal Phase 1 auth](decisions.md#minimal-phase-1-auth-no-passwords-no-jwt). Every endpoint that accepts a `user_id`/`trip_id` treats a malformed UUID as `422`, not `500`.

**Error convention:** FastAPI's default `{"detail": "..."}` body on all non-2xx responses. The specific status codes below are meaningful — the frontend branches on them (see `lib/api.ts`) rather than treating all failures alike.

### `GET /health`

## Routing — `/api/v1/routing`

### `POST /route`
Calculates a route and persists it as a `trips` row.

**Request body** (`RouteRequest`):
| Field | Type | Notes |
|---|---|---|
| `origin_lat`, `origin_lon`, `dest_lat`, `dest_lon` | `float` | required |
| `user_id` | `string \| null` | UUID; if present and found, loads stored `UserPreference` |
| `declared_intent` | `"hurry" \| "explore" \| string \| null` | `"hurry"` → `urgency=1.0`; `"explore"` → `urgency=0.2`; anything else is ignored |
| `waypoints` | `[{lat, lon}]` | ordered stops, routed through in sequence |
| `mode` | `"auto" \| "bicycle" \| "pedestrian"` | default `"auto"`; preference→costing translation only applies to `"auto"` |
| `origin_label`, `dest_label` | `string \| null` | human labels stored on `trips.context`, used later by the conversation layer |

**Response `200`** (`RouteResponse`):
```json
{
  "trip_id": "uuid",
  "routes": [ /* raw Valhalla `trip` objects — the deduped candidate pool */ ],
  "recommended_index": 0,
  "estimated_minutes": 12.4,
  "context_summary": "Route calculated based on your preferences.",
  "route_labels":     ["Fastest", "No highways", "Another way"],
  "route_strategies": ["fastest", "avoid_highways", "fastest"],
  "route_primary":    [true, true, false]
}
```

`routes[i]` is Valhalla's own response shape (`legs[].shape` polyline6-encoded,
`legs[].maneuvers[]`, `summary.{time,length}`) — the backend does not reshape it; the frontend's
`parseTrip()` decodes it. Requests set `directions_options.narrative`, so maneuvers carry
`street_names`, which is what lets the client name a route by the road it follows.

Each maneuver additionally carries, and the client now reads:

| Field | Used for |
|---|---|
| `type` | The turn arrow. An integer enum (0–43), mapped in `lib/maneuverIcons.ts`. |
| `begin_shape_index` / `end_shape_index` | Where the maneuver is performed / where its span ends. **`begin` is the turn point** — see `docs/decisions.md`, since using `end` puts every instruction one turn late. |
| `verbal_transition_alert_instruction` | Spoken at ~0.5 mi. |
| `verbal_pre_transition_instruction` | Spoken at ~150 ft. |
| `verbal_succinct_transition_instruction` | Spoken fallback when the two above are absent. |
| `verbal_multi_cue` | This line already named the *following* maneuver, so that one's warning is suppressed rather than said twice. |
| `sign` | Exit number and "toward" badges on the banner. |
| `roundabout_exit_count` | Drawn inside the roundabout icon. |
| `lanes` | The lane strip. **Not native Valhalla** — grafted on from a second OSRM-format call, see `docs/backend.md`. Absent on most maneuvers. |

Shape indices are **per leg**. `parseTrip()` concatenates every leg's coordinates into one array,
so it offsets each leg's indices by the running coordinate count. Consecutive legs share their
junction point and both copies are pushed, which is why the offset is `coords.length` with no
`-1`; de-duplicating that point later without changing this would slide every maneuver after a
stop by one position per leg.

Lane entries are OSRM-shaped: `{indications: string[], valid: boolean, active: boolean,
valid_indication?: string}`, one per painted lane in road order, left to right.

The candidates are **not** simply "Valhalla's primary plus its alternates". `routing/candidate_generator.py`
sweeps several costing strategies concurrently, pools every route each call returns, and de-dupes
on geometry overlap. The three parallel arrays describe that pool, index-for-index with `routes`:

| Field | Type | Meaning |
|---|---|---|
| `route_labels` | `string[]` | Display name — `"Fastest"`, `"No highways"`, `"Fewest turns"`, `"Shortest way"`, `"Calmer roads"`, `"No tolls"`. **Not unique**: every alternate Valhalla threw in alongside a strategy is `"Another way"`. Never key on this. |
| `route_strategies` | `string[]` | Machine key — `"fastest"`, `"avoid_highways"`, `"fewest_turns"`, `"shortest_distance"`, `"relaxed"`, `"avoid_tolls"`. Prefer this over matching labels, which are display copy and expected to get reworded. Mirrored into `trips.context["route_strategies"]`. |
| `route_primary` | `bool[]` | Whether a strategy actually optimised for this route. `false` means it is an alternate that rode along with some strategy's call — useful variety, but its label carries no information. The frontend uses this to decide between showing the strategy's name and naming the route by its dominant road (`"via S Cooper St"`). |

All three are additive fields with `default_factory=list`, so a client written against an older
backend degrades rather than breaking.

Under 2 straight-line miles the sweep is skipped entirely and only the baseline strategy runs —
probing showed no costing knob changes a short route, so the extra calls would only rediscover the
same road. Expect `["Fastest", "Another way", ...]` on short trips.

**Errors:**
- `422` — `user_id` not a valid UUID (also standard FastAPI validation errors for malformed body fields).
- Valhalla's own status code (typically `400`) with `detail` = Valhalla's error message — for unroutable points (outside the tiled region, not near a road).
- `503` — Valhalla unreachable.

### `GET /search`
Free-text place/address search via the [`MapDataSource`](architecture.md#backendmapdata--mapdatasource) abstraction (never a direct Overpass/Nominatim/Overture call).

**Query params:** `q` (string, required).

**Response `200`:**
```json
{ "results": [ { "lat": 32.735, "lon": -97.108, "display_name": "Panera Bread, ..." } ] }
```
No error path other than standard validation — an empty or failing provider degrades to an empty `results` array (see [Hybrid search data flow](data-flow.md#2-geocoding--place-search)).

## Users — `/api/v1/users`

### `POST /register`
Idempotent on email — re-registering an already-claimed email returns the same account (case-insensitive, whitespace-trimmed).

**Request:** `{ "email": "a@b.com" }` — validated against `^[^@\s]+@[^@\s]+\.[^@\s]+$`, max 255 chars.

**Response `200`** (`UserOut`):
```json
{
  "user_id": "uuid",
  "email": "a@b.com",
  "onboarding_completed": false,
  "preferences": { "avoid_highways": false, "avoid_tolls": false, "avoid_left_turns": false, "prefer_scenic": false, "max_acceptable_detour_minutes": 5 },
  "journey": { "typical_use_cases": null, "stated_dislikes": null, "home_location": null, "work_location": null, "known_regular_routes": [], "driving_persona": {}, "preferred_convo_style": "brief", "morning_routine_start_time": null, "typical_commute_duration_mins": null }
}
```
Registering also creates a `UserPreference` and `UserJourneyProfile` row with defaults.

**Errors:** `422` on a malformed email.

### `GET /{user_id}/profile`
Returns the same `UserOut` shape. If `preferences`/`journey` rows are somehow missing (pre-existing user, half-failed insert), they're healed in place rather than 500ing.

**Errors:** `422` bad UUID, `404` user not found.

### `PATCH /{user_id}/preferences`
Partial update — only fields present in the body change (`exclude_unset=True`).

**Request** (`PreferencesPatch`, all optional): `avoid_highways`, `avoid_tolls`, `avoid_left_turns`, `prefer_scenic` (`bool`); `max_acceptable_detour_minutes` (`int`, `0..120`).

**Response `200`:** the resulting `PreferencesOut`.

**Errors:** `422` bad UUID or out-of-range value, `404` user not found.

### `PATCH /{user_id}/journey`
Partial update, but with a deliberate null-handling distinction: for `home_location`/`work_location`, an **explicit `null`** clears the location, while an **absent key** leaves it untouched (`exclude_unset` distinguishes the two). For every other field, an explicit `null` is treated as "leave untouched" too (there's no clear semantics for nulling `preferred_convo_style`).

**Request** (`JourneyPatch`, all optional): `home_location`/`work_location` (`{lat, lon} | null`), `preferred_convo_style` (`"brief" | "chatty" | "silent"`), `typical_use_cases` (`string[]`).

**Response `200`:** the resulting `JourneyOut`.

**Errors:** `422` bad UUID, `404` user not found.

## Trips — `/api/v1/trips`

### `POST /{trip_id}/gps-update`
Appends a batch of GPS points to `trips.actual_path_taken` — atomically at the database, not read-modify-write (see [ADR](decisions.md#atomic-jsonb-append-for-gps-breadcrumbs-not-read-modify-write)).

**Request** (`GpsBatch`): `{ "points": [{ "lat": 32.7, "lon": -97.1, "timestamp": "2026-.../ISO8601 or omitted" }], }` — `1..1000` points.

**Response `200`:** `{ "trip_id": "...", "points": 47 }` — `points` is the array's new total length.

**Errors:** `422` bad `trip_id` or empty/oversized batch, `404` trip not found.

### `POST /{trip_id}/complete`
Marks a trip complete. **Idempotent** — a retried call returns the existing `completed_at` unchanged rather than double-processing.

**Request** (`CompleteRequest`, both optional): `duration_minutes` (`float >= 0`), `deviated` (`bool`) — stored verbatim under `implicit_signals.client_summary`.

**Response `200`:** `{ "trip_id": "...", "completed_at": "..." }`. Also sets `reward_value = 0.0` (`reward_source: "default_neutral"`) if nothing has set it yet — see [reward pipeline](data-flow.md#6-post-trip-debrief--reward-signal).

**Errors:** `422` bad UUID, `404` trip not found.

## Conversation — `/api/v1/trips` (mounted under the `trips` prefix, tagged `conversation`)

All routes here depend on an LLM client; if none is configured (`GEMINI_API_KEY` unset), every route in this section returns **`503`** with `detail` explaining why. The frontend reads `503` as "conversation features are off" and hides the UI rather than showing an error (see `openConversation`/`openDebrief` in `lib/api.ts`, which swallow the `503` into a `null` return rather than throwing).

### `POST /{trip_id}/conversation/open`
Idempotent per trip: a second call returns the already-persisted opener rather than generating a new one.

**Response `200`:** `{ "conversation_id": "...", "messages": [{"role": "assistant", "content": "...", "timestamp": "..."}] }`.

**Errors:** `422` bad UUID, `404` trip not found, `503` LLM unavailable.

### `POST /{trip_id}/conversation/reply`
Interprets a free-text reply into structured routing/preference actions.

**Request** (`ReplyRequest`): `text` (`1..1000` chars), `route_options` (optional `[{index, minutes, selected}]` — what's currently drawn on screen, needed to validate any `switch_to_route` the model proposes).

**Response `200`** (`ReplyResponse`):
| Field | Type | Meaning |
|---|---|---|
| `message` | `string` | assistant's acknowledgement (may have a found-stop or not-found suffix appended) |
| `intent` | `"hurry" \| "explore" \| null` | this-trip-only re-route hint |
| `preferences` | `object \| null` | present only when a durable preference was actually persisted |
| `switch_to_route` | `int \| null` | validated against the request's `route_options` — invalid indices are silently dropped to `null` |
| `stop` | `{name, lat, lon} \| null` | resolved via `_find_stop` (bbox around origin/destination, nearest candidate to the midpoint) |
| `stops_cleared` | `bool` | user asked to drop planned stop(s) |
| `set_destination` | `"home" \| "work" \| null` | client resolves the actual coordinates from its cached journey profile |
| `travel_mode` | `"auto" \| "bicycle" \| "pedestrian" \| null` | |

**Errors:** `422` bad UUID or invalid body, `404` trip not found or no conversation opened yet, `503` LLM unavailable.

### `POST /{trip_id}/debrief/open`
Generates the one-question post-trip debrief prompt; appends it to the trip's conversation (phase-tagged `"debrief"`), creating one if none exists.

**Response `200`:** `{ "message": "..." }`.

**Errors:** `422` bad UUID, `404` trip not found, `503` LLM unavailable.

### `POST /{trip_id}/debrief/reply`
Interprets the driver's debrief reply into a reward signal.

**Request:** same `ReplyRequest` shape (only `text` is used).

**Response `200`:**
```json
{ "message": "glad it went smoothly!", "reward": 0.8, "preferences": null }
```
Side effects: sets `trips.reward_value` and `implicit_signals.debrief`, stamps `completed_at` if not already set, and persists any extracted durable preference updates.

**Errors:** `422` bad UUID, `404` trip not found, `503` LLM unavailable.

## Voice — `WS /api/v1/trips/{trip_id}/voice`

A persistent WebSocket for the whole drive — not request/response HTTP. See [in-drive voice sequence](data-flow.md#4-in-drive-voice-websocket) for the full flow.

**On connect:** if no LLM is configured, the server closes immediately with code `1011` and a reason string (mirrors the HTTP `503` contract).

**Client → server frames** (JSON):
```json
{
  "type": "utterance",
  "mime": "audio/webm",
  "audio_b64": "...",
  "nav": { "destLabel": "...", "progress": 0.4, "minutesRemaining": 6.2, "nextManeuver": "..." },
  "routeOptions": [{ "index": 0, "minutes": 12.4, "selected": true }]
}
```
Non-`"utterance"` frames, non-JSON frames, and binary frames are silently ignored (the loop stays open). `audio_b64` is capped at ~7 MB (base64 of the same 5 MB raw-audio cap the HTTP `/speech/transcribe` route enforces).

**Server → client frames:**
| `type` | Payload | When |
|---|---|---|
| `"transcript"` | `{ "text": "..." }` | Always sent after transcription — empty string is a valid "no speech heard" outcome, not an error. |
| `"reply"` | `{ "text": "...", "action": {...} }` | Only when `text` was non-empty. `action` is byte-for-byte the same shape as the HTTP `ReplyResponse` (snake_case), including `message`, `intent`, `preferences`, `switch_to_route`, `stop`, `stops_cleared`, `set_destination`, `travel_mode`. |
| `"error"` | `{ "detail": "..." }` | Recoverable — no audio, audio too large, undecodable base64, transcription failure, trip not found. The socket stays open after this. |

Persisting the turn to `trip_conversations` is best-effort inside the handler — a DB error there is logged and swallowed, never torn down mid-drive.

## Speech — `/api/v1/speech`

### `POST /transcribe`
Server-side STT fallback for when the browser's Web Speech API returns nothing (a known Chrome failure mode — see the memory note on this if you're debugging it locally). Shared by both the pre-trip conversation UI and the post-trip debrief.

**Request:** raw binary body, `Content-Type` header carries the audio MIME type (e.g. `audio/webm;codecs=opus` — codec params are stripped before forwarding to the provider). Max **5 MB**.

**Response `200`:** `{ "text": "..." }` — empty string is a valid "no speech" result.

**Errors:** `422` empty body, `413` over 5 MB, `415` non-`audio/*` content type, `503` LLM unavailable.

## Feedback — `/api/v1/feedback`

### `POST /{trip_id}`
Stores raw post-trip free text (separate from the structured debrief).

**Request:** `{ "text": "..." }` (`1..2000` chars).

**Response `200`:** `{ "trip_id": "...", "stored": true }`.

**Errors:** `422` bad UUID or invalid text length, `404` trip not found.

## Tiles (not a backend route)

`GET /api/tiles/*` is proxied by the frontend dev server (and, in production, should be proxied the same way) directly to **Martin**, the self-hosted vector tile server — the FastAPI backend never sees these requests. See `frontend/vite.config.ts`'s proxy config and [ADR: self-hosted basemap tiles](decisions.md#self-hosted-basemap-tiles-planetiler--pmtiles--martin).
